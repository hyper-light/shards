# Response to the 2026-09-29 audit

Each finding of [the audit](2026-09-29_audit.md), what closes it, and the test that keeps
it closed. Work follows the audit's order: ownership and trust (A01–A05), externally
visible correctness (A06–A08, A11, A15), bounds (A09–A14, A16), recovery and portability
(A17–A20), then the comparison envelope. This file is updated as each change lands.

## Optimizations of the continuation

The continuation's designs, each with the correctness constraints it names; the audit
orders them after the findings above.

| ID | Item | Status | Change |
|---|---|---|---|
| D01 | Saving reads every page, and so materializes untouched RAM | fixed | The zero check reads words (M44), and a save of anonymous RAM skips the pages the OS says were never touched, neither resident nor paged out (macOS `mach_vm_page_range_query` after each map entry's counts, Linux pagemap), which read as zeros: 256 MiB with every 16th page used saves in 9.8 ms instead of 25.9, its peak RSS 22 MB instead of 268; RAM used throughout saves 1.0 ms slower (M54). A file-backed RAM's pages hold the file's bytes, and are read as before. `memory::tests::a_save_leaves_untouched_ram_untouched` (the save touches none of them; each page restored as it was; skip-all and skip-none mutants caught) |
| D02 | Prefetch spends private pages; pre-reading does not remove copy-on-write | open | |
| D03 | Restore metadata decoded, expanded and retained past startup | fixed | A restore keeps only what its release and diagnostics need (the counter, or vCPU 0's TSC and where it starts, and the prefetched count). The vCPU states, interrupt-controller and device state, and working set are dropped once every vCPU is set up, before the guest runs, where every warm VM held them: 127 KB for the test guest, plus 16 bytes per working-set entry (PM M58). The freed heap is the VM's to reuse; malloc keeps its pages, so a held VM's footprint does not visibly change. The decoder's second vector is reserved fallibly. The prefetch's transient buffers are bounded by the working set and freed before the guest runs, so they are left as they are. `snapshot::every_restore_continues_the_guest_where_it_asked_for_the_snapshot` checks the drop; a vCPU keeping its reference is caught |
| D04 | Linux file-backed RAM loses its mapping advice and is committed at full size | fixed | Commit: each held restore of a 256 MiB guest was charged 258.6 MiB with 20 KiB resident, and strict overcommit refused the 35th on a 16 GiB runner (PM M56). The file mapping is now MAP_NORESERVE, as a boot's RAM is, and is charged 2.6 MiB under modes 0 and 1; mode 2 ignores the flag and still charges each VM its RAM. `memory::tests::restored_ram_reserves_no_commit` reads its `VmFlags` (the mutant's `ac` is what M56's unpatched arm shows). The poll set is a six-slot array, whose sixth slot the full-duplex case needs. `frames::tests` (every two-way and byte-at-a-time split, a batch's partial tail, malformed streams, writes in any pieces); the mutants that compact on every write or never clear are caught, and the parser's cost is `frames_cost`'s |
| D08 | Output, input and log following copy and retain more than needed | fixed | A log record is written as its 13-byte head, on the stack, and the output where it is, in one writev that goes on through short and interrupted writes: no 65,549-byte copy per 64 KiB record.
