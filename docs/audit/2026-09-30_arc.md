# Shared ownership (`Arc`) audit

Started 2026-09-30. Rule: no `Arc` where ownership, borrowing or a narrower primitive will
do; each `Arc` that stays says why. Uses are fixed as the code around them is touched, and
this list tracks the rest. Counts are production uses (test modules and test crates aside).

## Done

| Where | Was | Now |
|---|---|---|
| `vm_run.rs` `serve_workload` | `Arc<Timing>`, `Arc<Mutex<Signals>>` shared with the workload and signal threads | `static`s: a VM process serves one workload (M34), and those threads live as long as it |
| `warm.rs` `receive` | a clone of the signals `Arc` per relay thread | `&'static ToGuest` |
| `bin/shards/client.rs` | `Arc<Mutex<Option<UnixStream>>>` shared with the signal forwarder | a `static`: one run per client process |
| daemon tests | `Arc<Daemon>` clones into spawned threads | `std::thread::scope` |
| `daemon.rs` | `Arc<Daemon>` (`self: &Arc<Self>`) for detached client, refill, recorder (`Weak`), stop and watch threads | every daemon thread is spawned in one `std::thread::scope` (`Threads`) that borrows the daemon, so none outlives it; the stop's escalation waits on the run table's condvar, ending with the last run instead of sleeping its grace periods out; tests run in `Test::run`, whose scope ends the daemon's threads and joins them, with a watchdog that aborts rather than hang |
| `vm/runtime.rs`, `vm/{aarch64,x86_64}.rs` | `Arc<Start>`, a restore's start, held by every vCPU through its setup, with a `Weak` count to check it had gone | `split` moves each vCPU its own state (and vCPU 0 the CPU check and working set), the machine keeps the rest, and vCPU 0 reports what it prefetched through the channel that reports its setup; nothing is shared, so nothing needs checking (PM M69: no cost on a run's path) |
| `registry/auth.rs` | `Arc<Handler>` per host, `Arc<Mutex<Option<Token>>>` per set of scopes | one lock over every host's handler and token slots, a slot `Fetching` or `Ready`, and a `Condvar`: one request fetches a token, with no lock held, while the rest wait; a host's generation keeps a late token out of a replaced challenge |
| `registry/http.rs` | `Arc<Pool>` cloned into each response's body | the client owns its pool; a `Response<'c>` borrows it to hand its connection back |
| `containers.rs`, `daemon.rs` | `Arc<dyn Disk>` held by the registry and cloned into each `Recorder` and `Removal` | the daemon owns its disk (`Daemon<D: Disk>`), and each registry write, record and removal borrows it for the call; tests reach their fake disk as `t.daemon.disk`, with nothing shared or leaked |

## Kept, and why

| Where | What | Why it stays |
|---|---|---|
| `daemon.rs` `Tracked`, `Inbox` | a run's socket, VM and inbox | a run's lifetime is its own: its thread follows it while any command may signal or settle it. One lock over every run would serialize their record writes; asking each run's thread would add a round trip per run to every command. `Arc` costs a few atomic operations per run, no lock and no round trip (user decision, 2026-09-30) |
| `daemon.rs` `Ready`, `State::starting` | a VM's `Child` | shared by its watcher, which waits on it, and by the pools and runs, which may kill it, each with its own lifetime |
| `daemon.rs` `clients` | a client's connection | shared by its thread and by a shutdown that ends it; a duplicate would cost a descriptor a daemon short of them needs |
