# D229 continuation: local limit observations and typed state

ROOT accepted the [pinned representation research](../../managed-cgroup-limit-otlp-contract.md)
and temporarily transferred the Reader/codec/fixture seams for this slice. This
table records the new literals and cardinality; it does not modify the broader
architecture decision or establish measured exporter cost.

| Literal / bound | Derivation and meaning |
| --- | --- |
| `Limit::Finite(u64)` / `Unbounded` | One shared pure codec-seam type. Existing kernel single-value `memory.max` / `pids.max` grammar, Linux6.18.48 pin in the research. Snapshot keeps `Result<Limit,Failure>` rather than numeric sentinels. |
| `shards.cgroup.memory.limit`, `By` | Accepted custom local configured-memory ceiling, exact kernel readback; UCUM bytes. Not effective parent cap, MemTotal, availability or entitlement. |
| `shards.cgroup.task.limit`, `{task}` | Accepted custom local configured task/TID ceiling; includes threads, not just process leaders. Singular count annotation follows pinned semconv1.45. |
| Gauge / `gauge` / `dataPoints` | OTLP1.11.1 sampled non-additive value; no temporality/isMonotonic/start-origin claim for these limits. Existing wire grammar reused. |
| `i64::try_from` range | NumberDataPoint.as_int is sfixed64. Only observed nonnegative finite values0 through i64::MAX have an exact integer point. Above-range finite becomes existing typed Overflow diagnostic while original state stays finite. No wrapping/clamping/type switch. |
| `shards.cgroup.limit.state`, unit `1` | Accepted separate Boolean-indicator Gauge. Independent of numeric-cap omission. Not an allocation/reservation ledger. |
| `shards.cgroup.metric` | Existing diagnostic attribute, one of the two fixed limit metric names here. Never a mutable Resource attribute. |
| `shards.cgroup.limit.state` values `finite`, `unbounded`, `unavailable` | Exhaustive classes of the original per-field Result<Limit,Failure>. Finite range conversion cannot change the original class. Successful max is not an error. |
| Indicator0/1 | `u8::from(state == observed)`: false/true proposition. Every state emitted each sample, exactly one true for each attempted field. A false indicator is never a synthetic zero-cap observation. Actual Finite(0) emits numeric0 independently. |
| Two limit fields ×three states =six state points | Derived from actual Snapshot fields and accepted enum classes, not a learned/default threshold. One state Metric descriptor per scope; at most two additional numeric Gauge descriptors/points when finite and representable. |
| Seven numeric observation slots | Five existing CPU/memory/tasks/read/write inputs plus two required local ceilings. Successful unbounded uses Ok(None); failures retain original typed cause and diagnostic counting. |
| Error count/details | Existing collection.error.count / collection.error, missing/invalid/overflow/io and errno retained. Each failed or unrepresentable limit adds one diagnostic, not three state-derived failures. No new error literal/default reason. |
| Three-Snapshot concrete fixture | Existing run/workload/member input, now with finite0/unbounded, actual typed failures, and finite range edges. Derived expected18 Metric descriptors /41 points /error counts0,6,2; these are fixture shapes, not production caps. |

Per actual scope the wire adds exactly six state points and zero through two
numeric limit points; failures may add up to two existing diagnostic points and
update the existing error-count Gauge. Two actual fixed-name reads reuse the
Reader's one fallible actual-page buffer. No extra getter, parent walk, cache,
polling, Resource identity field, stale marker, infinity encoding or authority
is introduced. Sequential collection remains non-atomic.

All point timestamps are the original Snapshot timestamp. Existing canonical
run/microVM IDs, stable member identity, unknown start and unsigned VMM lineage
string marker retain b57 semantics. No downstream deletion guarantee follows
from numeric omission. ROOT owns real caller/Collector/identity/cleanup/target
gates and measures actual bytes, CPU, allocations/faults and induced costs; no
overhead allowance, comparative result or whole-operation allocation claim is
made here. The profile file receives only input fields and is not executed.
