# Remaining memory policy designs

Implementer: Codex, findings memory-06..15. These are owed designs, not implemented
or validated replacements. The binding rule requires a local derivation and cold
start, not another chosen number. Broader learning/reclaim changes need ROOT's
real workloads, measurements and platform evidence before implementation.

| Finding | Required design and cold start | Failure/state handling | ROOT validation command |
|---|---|---|---|
| 06 pressure window / growth protection | Keep the Linux PSI minimum legal window inside that adapter. Drive budget updates by limit-change/completion events. Track growth as an outstanding request with observed block completions, rather than “grew within 2 s.” macOS/Windows repeat pacing needs a local cost/completion estimator. Cold requests remain Growing until completion or a typed device/VM end. | Separate Armed, Growing, Settled and Unavailable; no timeout may enlarge authority. | `cargo test -p shards moves_live --test moved` plus sustained/short pressure campaign concurrent with growth. |
| 07 PSI threshold | Learn the association between host stalls, charged room and reclaim outcomes on the running host, within user budgets. Available budget/OS pressure events remain authoritative during cold start. Research a sound way to arm PSI before that association exists; no inherited Android percentage is an accepted cold-start threshold. | TriggerUnavailable and InsufficientObservations remain explicit; do not report absence of pressure as measured health. | `cargo test -p shards --test budget a_microvm_held_to_a_budget_reads_through_fuse_at_the_pace_of_reads_held_to_none` plus unprivileged PSI/fallback variants. |
| 08 fallback polling | Replace fixed polling with an available OS event source. Where only an average is readable, derive observation cadence from local observation cost and actual changes; define the objective/authority for stale evidence before choosing an estimator. Cold start observes once, rather than sleeping first; it has no invented observation interval. | Report DegradedNoTrigger and unread statistics; a failed read is not zero pressure. | Same budget command as 07; inject trigger refusal and short pressure pulses. |
| 09 DAX crossover | Compare locally observed cold read, reread, overwrite and retained-memory costs by file-size class; collect enough uncertainty evidence before changing future inode policy. Cold start uses FUSE, whose semantics already work. Measurements cannot change write permission. Existing inodes must follow fuse_dax_dontcache lifecycle. | Sampling, FUSE and DAX choices explicit; failed/unsupported calibration stays FUSE with a typed reason. | `cargo test -p shards --test budget` and the existing D189 file-size/working-tree measurement harness, on supported hosts. |
| 10 headroom refresh | Prefer limit-change notifications; recompute room when an observed budget generation changes, charge admitted bytes until the next authoritative reading. Research handling of concurrent memory.current changes without the 100x cost coefficient. Cold cache begins empty and reads authority before admission. | Unknown room declines speculative retention and preserves the read itself; do not turn unread files into unlimited retention. | Budget command in 07 with concurrent limit changes and competing cgroup charges. |
| 11 reserve slack | Observe guest uncharged kernel usage and allocation overshoot at each growth/pressure transition; retain the separately derived page-structure and per-CPU terms. Establish a boot-safety derivation from the pinned guest and observed startup before removing 64 MiB. | Unknown reserve must not silently mean zero or enlarge guest room; return a typed unavailable/startup refusal if startup cannot be shown safe. | `cargo test -p shards --test build a_builders_memory_is_plugged_as_fast_as_its_jobs_take_it` plus CPU-count/cold-builder variations. |
| 12 pause/read floor | Grower should wait on actual memory-online and driver/VM lifecycle notifications, recording completion cost independently of scheduler holds. At an expired Giver deadline, perform a readiness/nonblocking check without adding 1 ms. Unix Polled and Windows reads need matching deadline behavior; simply removing SO_RCVTIMEO can block indefinitely. | Waiting, Held, Completed and DriverEnded remain distinct. An unread host/driver fails typed. | `cargo test -p shards --bin shards build::give::tests::` and `cargo test -p shards-init plug::tests::` on Linux, then builder VM growth command in 11. |
| 13 retry count | Replace the two-attempt decision with observed request/completion and driver terminal-state events. A delayed but active driver should remain pending, not be called Stalled solely because a fixed number of windows elapsed. Cold start follows driver/VM liveness. | Represent the retry/driver request generation explicitly, preserve cancellation and refusal. | `cargo test -p shards-init plug::tests::` with delayed third-window completion, then actual virtio-mem retry/pressure fault injection. |
| 14 growth/retention ratio | Derive speculative headroom from locally observed allocation bursts, online latency, reclaim and available room. Preserve peak since pressure and protocol block alignment. Cold start grants only derived startup need and grows from actual pressure/completion observations; no fixed multiplicative guess. | Pending growth and pending shrink cannot revoke one another; unknown cost is explicit and cannot exceed the user's ceiling. | Builder VM command in 11 and `cargo test -p shards --test build a_build_held_short_of_memory_has_its_builder_give_back`. |
| 15 boot floor | Derive the pinned guest's startup requirement (kernel/init/page structures/CPUs) and refine from startup observations per compatible guest/host identity. This requires cold-start evidence before replacing 512 MiB. Do not rely on successful warm history to prove a different architecture boots. | Unknown minimum is a typed startup prerequisite/refusal, never a guessed replacement or zero allocation. | `cargo test -p shards --test build a_builders_memory_is_plugged_as_its_build_needs_it` across cold homes and CPU/architecture variants. |

All commands above are owed to ROOT and were not run by this lane. Test-only
clock/deadline values in focused regression cases are not production policy.
The precise learner for 06..15 remains a design/research obligation; this file
does not approve a speculative estimator or claim the existing constants comply.
